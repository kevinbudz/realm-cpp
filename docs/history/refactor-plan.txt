## Facts that shape the plan

- `application::run()` (`src/application.cpp:128` to the end) is 1,572 lines, with 15 `FunctionLayer` registrations, about 53 capturing lambdas, and about 40 branches on mode and option flags.
- Two UI backends: RmlUi (default) and a native GL-texture path. The native path also feeds the Q09 pilot comparison.
- `Startup` (`src/startup.cpp`, 1,469 lines) builds a view model for RmlUi. `src/startup_rml.cpp` consumes it, so the model stays even though parts of it look native.
- `RetainedSurface` (`include/realm/ui_retained.hpp`) switches between a native `SurfaceTexture` path and an RmlUi snapshot path through `rml(bool)`.
- `--client` implies `--hud` (`src/application_options.cpp` line ~146), so the RmlUi host exists in every client run.
- `REALM_RMLUI` is a CMake option guarding about 47 `#if` lines, plus `cmake/ClientTargets.cmake`, `cmake/ClientBoundaries.cmake`, and `cmake/header-owners.json`.
- Oracle env switches: `REALM_TARGET_SEARCH` (`src/combat.cpp:21`), `REALM_DYNAMIC_ATLAS` (`src/application.cpp:242`), `REALM_DYNAMIC_ATLAS_PAGES` (`=0` disables the atlas), `REALM_DYNAMIC_ATLAS_INITIAL`, `REALM_ATLAS_GROW_FRAMES`, `REALM_ATLAS_PROTECT_FRAMES`, and `REALM_RMLUI_PULSE` (pilot only). Only the first few are oracles. The others are sizing knobs.
- Env knobs that stay: `REALM_AUDIO`, `REALM_AUDIO_DEVICE`, `REALM_AUDIO_CACHE_MB`, `REALM_SFX_ROOT`, `REALM_UI_ACTION_TRACE`, `REALM_QUAD_CHECKSUM`.
- Harness surface: 66 CLI flags in one parser (`src/application_options.cpp`), including `--stress*`, `--reference-render`, `--sprites`, `--texture`, `--raw-flash-bitmap`, `--projectile-*`, `--text`, `--font-*`, `--sheet`, `--scale`, `--frames`, `--scene-time`, `--status-age`, `--ghost`, `--ally*`, `--damage*`, `--hp`, `--breath`, `--condition`, `--background`, `--effect-time`, `--notify`, `--offset`, `--fixture-step-ms`, `--benchmark`, `--orphan-stream`, `--telemetry*`, `--trace`, `--capture`, `--map`, `--world`, `--script`, `--fonts`, and `--hud-art` (both already ignored).
- Harness executables and tests: 25 `tools/*_inputs.cpp`, 22 `tests/*inputs.cpp` and `*_session_inputs.cpp` files, 19 `tests/*_reference_tests.py` files. About 57 Python tests reference Flash, AIR, or a live server (rough grep).
- Reference data: `fixtures/client-quality/v1` (65 files) and `tools/flash-reference/` (AS3 exporters plus `build_flash_reference.py`, `font_reference.py`, `import_flash.py`).
- Keep: the asset pipeline that feeds the build (`compile_*.py`, `bake_*.py`, and the generated `flash_*.hpp` headers) and `assets/*.bin`. The product still reads art, XML, and fonts from the Flash source tree (`--flash-root`).
- Large classes: `Startup` (screen state, HTTP tasks, layout), `World` (~20 responsibilities), `Renderer` (dozens of GL handles, post-processing, GPU timers), and `Entity` (about 30 public fields).
- Duplicated helpers: `stat()` in `src/hud.cpp:51`, `src/inventory.cpp:5`, and `src/item_tooltip_content.cpp:17` (identical bodies). `number()` in `item_tooltip_content.cpp`, `startup_rml.cpp`, `ui_retained.cpp`, and `catalog.cpp`. `code_points()` in `chat.cpp`, `startup_rml.cpp`, and `ui_pilot_native.cpp`. `pending()` in `http.cpp` and `transport.cpp`. `integer()` in `account.cpp` and `application_options.cpp`.
- Tests are named by verification mode (`_gpu_`, `_live_`, `_reference_`, `_http_`), not by subsystem. No CTest labels. `CMakeLists.txt` is 30 KB, with 75 hand-written `add_executable`/`target_link_libraries`/`add_test` triples.
- One feature (party arrows) spans nine files across `src/`, `include/`, `tools/`, and `tests/`.
- Style: no `.clang-format`. About 2,500 of 24,000 src and header lines exceed 120 columns. About 1,500 lines hold several statements. About 1,470 single-line `if`s lack braces. Both `if(` (3,046) and `if (` (688) appear.
- Dead docs: the README links six files under `docs/client-quality/`, deleted on purpose in commit `61f86a2`. `docs/progress.md` (1,285 lines) points to a deleted `AGENTS.md`.
- Process labels in code: about 10 `src`/`include` lines and 24 test/tool lines mention Q-numbers as history.
- Repo hygiene: nine `build*` directories at the repo root (gitignored). `.claude/agent-memory-local/` is tracked (3 files).
- Keep: `cmake/ClientBoundaries.cmake` (link boundaries enforced at configure time), one header per `src` file, `include/realm/ui_stack.hpp` (input ownership), sanitizers, CTest, live-server tests, and the quad checksum oracle.

## Phases (each phase leaves Release building and CTest passing, except where noted)

**Phase 1. Remove the native UI backend, the Q09 pilot, and the oracle env switches.**
- Startup (`src/startup.cpp`, `include/realm/startup.hpp`): delete `build()`, `uploads_`/`uploads()`/`clear_uploads()`, `pulse_texture_`, `skin_texture_`, `skin_native_stale_`, `native_view_`, and `set_native_view()`. Take the RmlUi branch of every `native_view_` check. Keep the element model, `sheet()`, `store()`, `changed_regions_`, `view_uploads_`, `hit()`, and the pointer and key methods.
- `RetainedSurface`: remove the native `SurfaceTexture` member and `rml(bool)`. Update `tests/ui_retained_tests.cpp` (native test around line 86).
- Application (`src/application.cpp`): remove every `#ifdef REALM_RMLUI` and the `UiSurface` alias. Remove the native `else` branches for startup, the startup layer (around lines 740 to 765, including the native `is_text` fallback), and surfaces. Remove all pilot code. Remove the `REALM_DYNAMIC_ATLAS*` and `REALM_ATLAS_*` reads (around lines 240 to 243) and hard-code 12 pages, 2 initial, 120 grow frames, and 2 protect frames. Keep `text_ui && hud_art && (o.client || o.world)` for `production_ui`. Rename `production_ui` once it is the only UI.
- Options: remove `ui_backend`, `ui_pilot`, `ui_pilot_summary`, their parse entries, and their help text. Remove `dynamic_atlas_*` and `environment_integer` if unused.
- Oracle reads: remove the `getenv` for `REALM_TARGET_SEARCH`. Keep `TargetSearch::scan` (`include/realm/combat.hpp`) and `Scene::set_dynamic_atlas(bool)` as test-only reference APIs, since `tests/combat_target_tests.cpp` and `tests/dynamic_atlas_tests.cpp` need them. Reword their comments as test-only.
- Delete the pilot: `src/ui_pilot*.cpp`, `src/ui_pilot_rmlui.hpp`, `include/realm/ui_pilot*.hpp`, `tests/ui_pilot_gpu_tests.py`, `tests/ui_pilot.script`, `tests/ui_pilot_phases.json`, `tools/ui_pilot_bench.py`.
- CMake: make RmlUi unconditional (remove the option and its guards). Remove `realm_ui_pilot` and its tests. Update `cmake/ClientTargets.cmake`, `cmake/ClientBoundaries.cmake`, `cmake/header-owners.json`, and the test list near line 398 of `CMakeLists.txt`.
- GPU tests: remove the `--ui-backend native` variant from `death_fame`, `delete_character`, `hud_overlay`, `legends`, `skin`, `startup_parity`, `ui_bundle`, and `ui_resize`.
- Check `tests/client_boundaries_tests.py`, `tests/ui_rml_host_tests.cpp`, `tools/quality_stress.py`, and `tools/quality_baseline.py` for pilot or backend references.
- Verify: `ctest --preset release`. Expected: the baseline failures, minus the removed pilot tests. Compare the Phase 0 captures.

**Phase 2. Remove the harness and the Flash parity tooling.**

- Remove the harness flags listed under "Harness surface" from `src/application_options.cpp` and the code paths they select. Keep the product flags: `--client`, `--connect`, `--server`, `--app-port`, `--port`, `--username`, `--password-stdin`, `--character`, `--create`, `--game`, `--account-file`, `--settings-file`, `--flash-root`, `--audio`, `--hidden`, `--width`, `--height`, and `--help`. Keep `REALM_QUAD_CHECKSUM` (the oracle).
- Delete the harness executables: the 25 `tools/*_inputs.cpp` and the `tests/*inputs.cpp` / `*_session_inputs.cpp` files, with their CMake entries.
- Delete the 19 `tests/*_reference_tests.py` files, `fixtures/client-quality/`, and `tools/flash-reference/`. Delete `tools/build_flash_reference.py` and `tools/font_reference.py`. Keep `tools/import_flash.py` and the `compile_*.py` and `bake_*.py` generators only if the build still needs them (check `flash_manifest`).
- Delete the Python tests whose only job was Flash comparison or harness input. For each remaining Python test, keep it only if it checks product behavior without Flash output. Those tests get re-labelled in Phase 6.
- Verify: release build, then `ctest --preset release` on the remaining tests. Expect fewer tests. Record the new count and its exact list in the scratchpad.

**Phase 2 decisions (user, 2026-10-13, after the inventory):**
- realm_viewer goes. realm_client is the only binary. Its default mode is the startup flow. `--connect` (direct live join, with --username/--password-stdin/--character/--create/--game), `--map` (offline world) and `--stress`/`--stress-summary` (the rendered stress path that holds the REALM_QUAD_CHECKSUM oracle) are documented test-only modes.
- Kept test hooks: --script, --hidden, --frames, --benchmark, --fixture-step-ms, --stress-delay, --capture, --width/--height, the status fixture flags (--hp --condition --breath --ghost --ally --ally-name --notify --damage --damage-effects --status-age --effect-time --scene-time), and the telemetry flags --telemetry, --trace and --telemetry-warmup.
- Removed: --client, --hud (always on), --world (internal), --fonts/--hud-art, --text/--font-*, --texture, --raw-flash-bitmap, --projectile-*, --sheet, --sprites, --scale, --offset, --background, --reference-render, --orphan-stream, plus the gallery and camera fixture.
- Kept drivers: realm_session, realm_stress, tests/*_session_inputs.cpp, delete_stale, skin_http. Deleted: all tools/*_inputs.cpp except stress_inputs (Flash comparison), options_source (Flash parity), and the 34 Flash-reference Python scripts. Deletion follows the inventory's classified list, not the `*_reference_tests.py` name pattern, which misses 15 of them.
- fixtures/client-quality/v1 is stress workloads plus HTTP replies, not Flash data. It moves to tests/fixtures/.

**Phase 3. Formatting, as one pass with no logic change.** Add `.clang-format` with `BasedOnStyle: Google` and `ColumnLimit: 120`. Google's default of 80 columns would wrap thousands of lines in this dense codebase. Naming stays as it is (snake_case functions, trailing-underscore members). Google style governs layout only. Run `clang-format -i` over `src`, `include`, `tests`, and `tools`. Verify with a full build and the checksum. Doing this after the deletions keeps the churn smaller.

**Phase 4. Split `application::run()`.** With only `realm_client` left, the run loop is simpler. Move it into a `Coordinator` with separate methods for startup screens, the in-game loop, and shutdown. Move each `FunctionLayer` group into its own class under the UI views target. Keep the 15 registration order, since `ui_stack` depends on it. Verify with CTest and the checksum.

**Phase 5. Consolidate duplicated helpers.** Add `Entity::stat(flash::StatId, int fallback)` or a `StatMap` method, and replace the three `stat()` copies. Move `number()`, `code_points()`, `pending()`, and `integer()` into shared headers. Verify with CTest.

**Phase 6. Tests and CMake.**
- Add CTest labels to every remaining test: `unit` (headless, no deps) and `gpu` (needs GL). Add `live` for tests that need the server. Verify `ctest -L unit` runs without a server.
- Add a `realm_add_test(NAME ... SOURCES ... LINK ... ARGS ... LABELS ...)` CMake function to replace the hand-written triples in `CMakeLists.txt`.
- Add `tests/README.md`: a matrix of each label, its prerequisites, and how to run it.
- Rename test files by subsystem where the rename is cheap.

**Phase 7. Split the large classes, one at a time, as they are touched.**
- `Startup`: separate screen state, an HTTP task service (`std::async` with generation checks), and the view model.
- `World`: move particles, status text, and sound cues into owned subsystems.
- `Renderer`: extract post-processing, GPU timers, and stream buffers.
- `Entity`: make fields private with accessors, or group them into sub-structs.
- Verify each split with the checksum and CTest.

## Final history: squash to one "Initial commit"
