## Implementation

- `src/scene.cpp`, `include/realm/scene.hpp`: one catalog lookup and one depth projection per camera-visible entity (`Visible{entity,def,depth,id}`), reused by the under, shadow and painter passes (previously four lookups per entity and two camera projections per sort comparison). `scene.sort_entities` now sorts those contiguous records. The painter stream merges the already-ordered entity run with the (few) particles instead of sorting everything again: with non-negative ids every entity precedes every particle at equal depth, so the merge equals the old full sort; a negative id (rare) keeps the original single sort. `Scene::set_culling(false)` is a differential oracle (never off in the client).
- Conservative bounds: the 400/100/400 px margins on the ground point are unchanged and hold for every sprite at legal sizes (largest catalog Size 400, tested to 500). The test found a real bug in models: a model's footprint/height is not covered by 100 px at the top edge (e.g. `Jacko` radius 2.7 tiles, `Large Monument 3` 3.8 tiles tall), so wide models vanished up to **68 px** short of leaving the top of the screen (26 missing model quads in 63 test configs). `model_extent()` (`src/model.cpp`) gives each family's radius/top/bottom; offscreen model objects are re-tested against their own extent (`Scene::model_reaches`, cached per definition).
- Shadows are deliberately culled with their entity (like Flash, which draws nothing for objects on non-visible squares): a radial shadow scales with entity size × shadow size × sprite height and can span thousands of pixels, so one whose ground point is far offscreen is not built. Sprites beyond ~600% size (not legal in the catalog) can outgrow the margins.
- `src/world.cpp`, `include/realm/world.hpp`: `World::interactive_target` visits only a maintained list of interactive entity ids (add/remove/initialize keep it), with the same strict-`<`/earliest-in-dense-order tie rule as the scan; `src/appearance.cpp` `world_dyes` finds the deciding merchant in one entity pass instead of four (same neighbour order, same first-entity rule).
- Telemetry/tools: permanent zones `world.interactive_target`, `scene.world_dyes`, `minimap.update` (`minimap.markers`, `minimap.render`), `party.update`; stress summaries gain `quad_stream_checksum` (an order-sensitive digest of every submitted quad and mesh vertex, computed only with `REALM_QUAD_CHECKSUM=1`).
- Tests: `tests/world_query_tests.cpp` (CTest `world_queries`) and `tests/visibility_tests.cpp` (CTest `visibility_culling`, graphics builds).
- Not changed: gameplay, collision, protocol, combat, `World::update`, terrain culling, particle/flash logic. Visibility is render-only, so offscreen authoritative state, projectiles and acknowledgments are untouched (state/packet checksums and hit counts are identical in all 59 paired scenarios).

## Differences, failures and limitations

- Whole-client S3/144 Hz is still **unqualified**: S3 frames are 140–800 ms and dominated by name/appearance work (Q07) and the minimap redraw (Q12), neither a world query. This task removed about 2 ms (S3) / 2.6 ms (S4) of per-frame query/sort cost and fixed a visible model-culling bug; it did not move whole-frame p95.
- No spatial grid was added for the camera: with all objects in view (the S3/S4 fixtures) a grid cannot cull anything, and spread cases cost 0.2–0.7 ms to scan; reintroduce it only if a zone shows otherwise. Concentrated cells have no special cost in these paths (they are linear scans, not cell lookups). `World::update` remains one pass over all entities (0.1–0.6 ms; bound by `Entity` size, a Q05 layout question).
- `interactive_target` relies on `Entity::type` never changing after `World::add`; nothing in the tree does, and the differential test would fail if the list went stale.
- `flash_tint` still loops all (≤256) active flashes per drawn entity; flashes were 0 in every fixture, so it was not touched (worst case 256 x visible compares, a few ms).
- Shadows of objects whose ground point is offscreen are culled with them (Flash behavior); entities scaled beyond legal sizes (~600%+) can still outgrow the margins. Documented rather than extended.
- The first 5-repeat control run flagged nexus-idle 1.108 and determinism 1.0535 (>5%); both are ~0.2–0.5 ms absolute with overlapping repeat ranges, and a 9-repeat rerun gave 0.96 / 1.00. Recorded as noise, not hidden.
- Pre-existing unrelated warnings remain in `tests/dye_session_inputs.cpp`, `tools/skin_inputs.cpp`, `tests/player_menu_tests.cpp`. No required check was disabled, skipped or blank. No new visual captures: painter streams are byte-identical to the previous implementation in 57/59 scenarios and differ only by added edge models in 2; mock/offline evidence, not live server.
