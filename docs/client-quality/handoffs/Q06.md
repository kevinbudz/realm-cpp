## Baseline (pre-Q06 binary, `build/quality-Q06/viewer-before`)

Per model per frame `project_model` transformed every vertex in double, culled/shaded each face, allocated a `std::vector` of screen points, a `shared_ptr<MeshDraw>` and a growing vertex vector (~9 allocations); the renderer then switched program/VAO twice, orphaned and re-uploaded the mesh with `glBufferData`, and issued one draw per material group. S3 dense models (2,966 drawn): `model.prepare` 1.43 ms, `render.model_upload_submit` 3.27 ms, 1.83 MB mesh upload, 3,700 draws, GPU 3.29 ms, 27,822 allocations / 7.3 MB per frame. S4 doubled all of it.

## Implementation

- `include/realm/model.hpp`, `src/model.cpp`: `model_geometry()` — all 42 models expanded once (3,456 vertices, 124 KB) into model-space triangles in the stored fan order `(i, 0, i+1)`, each vertex carrying the face normal (vertex `i`'s, exactly what `project_model` shades with), UV and a Solid flag; `model_range(index)`; `model_index(name)` (hash lookup; `has_model`/`project_model` use it instead of a linear `strcmp` scan); `model_quad(...)` builds one allocation-free painter-stream `Quad` (kind 9, no owner): the camera and Z rotation are affine, so `origin`/`axis_x`/`axis_y`/`uv_offset` hold the screen transform of model x/y/z, `offset` = (cos, sin) of the object rotation and the model index, `uv`/`page` the sprite rectangle, `multiply` the flat color with alpha = "has sprite". `project_model` is kept unchanged as the CPU reference.
- `src/renderer.cpp`, `include/realm/renderer.hpp`: a model program whose static vertex buffer is the persistent geometry (uploaded once) and whose instance attributes are read straight from the already-uploaded quad buffer (divisor 1). A contiguous block of model quads switches program once; each run of consecutive copies of one model is one `glDrawArraysInstanced` (GL draws instances in order, so painter order is exact). The vertex shader applies the affine transform and the Flash flat shade `0.75 + 0.25 max(0, n·normalize(1,3,2))` with the object-rotated normal (`flat` varyings); the fragment shader is the previous textured/Solid one. GL back-face culling (front = CCW in window space, enabled only for model draws) applies the same screen winding rule to the stored order. Owned `MeshDraw` quads (reference path) still draw as before. GPU model timers now time model draws.
- `src/scene.cpp`: one `model_index` lookup and `model_quad` per model (was `has_model` + `project_model`).
- `src/stress.cpp`: instance triangles counted from the model range; `REALM_QUAD_CHECKSUM=models-as-markers` digest mode (all non-model quads in full, models as markers).
- `tools/model_inputs.cpp`: the Flash-reference tool's direct path uses `model_quad` (`REALM_MODEL_REFERENCE=1` draws the CPU reference instead).
- Tests/tools: new GL test `model_instances` (`tests/model_instance_tests.cpp`); `telemetry_gpu` model scene now uses 8 different models per row so >32 model draws still exercise the timer budget, and asserts zero per-frame mesh uploads; `tools/quality_zones.py` (zone/counter medians, either side of a `--compare` run).
- Not changed: painter order/depth sort, material selection, sprite choice, culling extents, `SpiderWeb` rule, Flash lighting, gameplay/protocol. No depth buffer.

Evaluated and not done: a single draw for a contiguous block of *different* models needs base-instance/`gl_DrawID` (GL 4.2/4.6) or padding every model to the largest vertex count; remaining cost at S3 dense is 0.67 ms for ~3,100 draws, so it is not justified yet.

## Differences, failures and limitations

- Visual: GPU float transform vs CPU double flips a few edge pixels (1 of 2.07 M pixels in one 1080p capture; 1 pixel in 110 reference frames; 49 of 27.8 M in the differential test). Edge-on faces under 0.001 px thick may be kept by one path and culled by the other; they cover no pixel centers in practice.
- Fully back-facing models now submit an instance quad (the GPU culls every face) where `project_model` returned null; no scenario's submitted counts or marker digests changed.
- `triangles` now counts all model triangles before GPU culling (about 2x the kept faces) and `models_measured` counts measured model draws; documented in [../telemetry.md](../telemetry.md).
- Mixed-scene GPU time is 2–4 % higher (S1-mixed-dense 1.45 -> 1.51 ms, S3-mixed-spread 6.51 -> 6.65 ms world median) because back faces now reach the GPU; CPU savings there are larger (0.4–1.2 ms). Model-only scenes are 25–75 % cheaper on the GPU (no per-model buffer orphaning).
- Varied adjacent models still cost one draw each (~0.2 us); see "Evaluated and not done".
- **S3/144 Hz remains unqualified**: S3 mixed-spread p50 18.6 ms, p95 71 ms. Models are no longer a material part of it; the remainder is `scene.build` (projectile/actor appearance and text, ~8 ms) and first-seen composition hitches, which are Q07.
- Graphics sanitizer subset count (23) differs from Q05's (24) because the subset regex differs, not because a test was dropped; all graphics tests matching it passed. Pre-existing unrelated warnings noted in Q05 were not touched. Mock/offline evidence only.
