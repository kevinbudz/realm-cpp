## Implementation

- `cmake/ClientTargets.cmake`: support, platform, network, game, CPU assets, UI,
  fixtures, render, SDL platform, startup adapter and application libraries.
  `CMakeLists.txt` links actual owners instead of recompiling renderer/atlas/scene/
  startup in executables. Private SDK dependencies stay in backend adapters.
- `cmake/ClientBoundaries.cmake`, `cmake/header-owners.json`,
  `tests/client_boundaries_tests.py`: configure-time direct-link policy and a
  CTest audit of the actual source/link graph, public interfaces, upward includes,
  unique source owners and SDK leaks; three negative controls.
- `draw_types.hpp/.cpp`: CPU quad/model descriptions and math without GL headers.
  `model.hpp`, `stress.hpp` and `backdrop_data.hpp` now support headless consumers.
  `Atlas`/renderer/scene use fixed-width handles and backend implementation files
  include GL explicitly. Typed renderer metadata/error helpers remove the
  coordinator's direct GL include.
- `application.cpp`: one compiled coordinator for viewer and client. Eight-line
  `main.cpp` passes only the initial mode. Parsing/config, script reading and
  offline-map setup move to separate internal application files; the coordinator
  is 1,298 lines. Live state still comes from production Session/World.
- `platform.cpp`, `platform_sdl.hpp/.cpp`: RSS query, SDL context/window and cursor
  lifetimes. The application loads cursor artwork and transfers owned RGBA bytes
  to the platform adapter; platform does not depend on assets/game. Construction
  order still destroys all GPU resources before the context and quits SDL last.
- `tests/sdl_keys_tests.cpp`: initialize video before querying key/scancode maps;
  the old standalone test fails under SDL 2.32, while the application already
  initializes it. All 141 checks now pass.
- `tests/ui_resize_gpu_tests.py`: explicit binary/output directories and timeout,
  plus the existing 20 ms fixture clock. Wall-time capture deadlines were missed
  under software-renderer/build load; the fixed clock exercises every stage.

No external libraries, runtime backend, gameplay rules, UI design, art or resource budgets
were replaced. No server/web work or user account changes. Ownership, diagrams,
interface rules and reproduction are in `docs/client-quality/architecture.md`.

## Differences, failures and limitations

- The whole client is not certified as passing: `dynamic_atlas` fails on this
  software driver in both original Q07 and Q08. Original sources were archived
  from 62bf938 and built independently. Both start at roomy frame 3, pixel
  (409,14): dynamic RGB 70,40,49 vs standalone 71,40,50. The test stays strict;
  no pixel tolerance or test disabling was added.
- Q07's `src/appearance.cpp:23` world_dyes overflow remains on intentionally
  non-finite world_queries inputs. Both source/test are unchanged, and no UBSan
  report is suppressed. A passing CTest exit does not mean sanitizer-clean.
- Startup picks background_y with random_device, so whole menu image equality
  is not a valid cross-process check. Seeded stress captures and independent
  pulse fixtures provide deterministic checks; UI/input geometry is exercised.
- Measurements are short, offline, same-host software-renderer comparisons.
  They do not qualify capacity, real-server behavior or hardware/display latency.
  Allocation tracking is off on both timing binaries; memory/cache summaries
  and churn/outcome checks are recorded instead. Existing cache budgets remain.
- Startup remains a render-aware adapter because it owns retained surfaces;
  Q10/Q11 own migration to the selected shared UI foundation. The pure UI target
  remains headless. The coordinator still owns cross-controller/frame routing.
