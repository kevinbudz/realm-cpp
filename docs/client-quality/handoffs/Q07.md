## Implementation

- `include/realm/atlas.hpp`, `src/atlas.cpp`: the sprite `Atlas` texture array gets dynamic layers after its 2 static layers (same layer indices for static art). `upload_dynamic` writes a premultiplied copy exactly as `SurfaceTexture` does; `resize_dynamic(n)` reallocates the array and copies all static layers and kept dynamic layers on the GPU (`glCopyImageSubData` with GL 4.3/ARB_copy_image, else per-layer framebuffer blits with the scissor test saved/disabled), zeroing new layers. `Atlas::force_blit_copy` lets tests exercise the blit path.
- `include/realm/residency.hpp`, `src/residency.cpp` (new, headless, `realm_core`): `TextureResidency`, a shelf allocator over the dynamic pages with LRU eviction. Height classes round up to multiples of 8 (<64), 16 (<128), 32 (<256), 64; per-shelf free x spans and per-page free row ranges, first fit, coalesced; an empty shelf returns its rows. Slots never move. Protection window: an entry used within the last `protected_frames` frames (client: 2) is never evicted, so a frame's queued quads can never see a reused slot, and with a working set above capacity the steady visible set stays resident while the excess goes to the fallback instead of cyclic re-uploads. Growth: when an insert would have to evict an entry used within `recent_frames` (client: 120) and pages are below the cap, it requests `min(max, 2·pages)` pages instead of evicting.
- `include/realm/appearance.hpp`, `src/appearance.cpp`: `Appearances::Key` is public; `animated_key`/`texture_key`/`image(Key)` (one path; `animated`/`texture` are now wrappers, behaviour unchanged); `set_budget`.
- `include/realm/scene.hpp`, `src/scene.cpp`: composed appearances are resident by content key (a resident appearance does no CPU cache lookup and holds no CPU image; a CPU eviction no longer forces a re-upload), labels/icons by image identity with a weak_ptr guard. Resident bitmaps become ordinary atlas quads (`texture == 0`, kinds 5/6/8 unchanged) and batch with sprites, shadows and bars. Projectile outline squares are clipped to their slot on the CPU (axis-aligned in uv space, so the cut is exact). Anything that does not fit (larger than a page, or every slot protected at the cap) takes the old per-image `SurfaceTexture` path unchanged; the overflow caches are 16 MiB each while the atlas is active. A map change shrinks the atlas back to its initial size. `set_dynamic_atlas(false)` is the differential oracle (old path for everything); `resident_images()` is a diagnostic for the readback test. `status_quad` serves floating status text (main.cpp) from the atlas.
- `src/renderer.cpp`: atlas-sampled kinds 5/6/8 clamp to their region's texel centres like sprites; the `[0,1]` clip applies only to standalone surfaces. Mode 4 (static projectile crop) unchanged.
- `src/main.cpp`: atlas built with 2 dynamic pages, cap 12; env `REALM_DYNAMIC_ATLAS_PAGES` (cap, 0 disables), `REALM_DYNAMIC_ATLAS_INITIAL`, `REALM_ATLAS_PROTECT_FRAMES`, `REALM_ATLAS_GROW_FRAMES`, `REALM_DYNAMIC_ATLAS=0` (oracle); exit summary prints pages/resizes/evictions/fallbacks.
- Telemetry (`include/realm/telemetry.hpp`, [../telemetry.md](../telemetry.md)): counters `atlas_uploads`, `atlas_evictions`, `atlas_fallbacks`, `atlas_resizes`; gauges `atlas_resident_bytes`, `atlas_shelf_bytes`, `atlas_pages`.
- Tests: headless `texture_residency` (`tests/texture_residency_tests.cpp`) and GL `dynamic_atlas` (`tests/dynamic_atlas_tests.cpp`), registered in `CMakeLists.txt`.
- Not changed: composition (`compose`), dyes/masks, shadows, painter order, HUD/portrait CPU consumers of `Appearances`, gameplay/protocol.

Evaluated and not done: prewarming composition (the remaining S3 tail is first-seen composition of up to ~3,000 new appearances in one frame; caching cannot remove it, and precomposing every animation frame/dye/size combination ahead of visibility is speculative — a candidate for Q18 concurrency or a spread-over-frames compose budget); per-pixel-identical tie breaking (impossible in general: hardware converts uv to fixed point relative to the texture size, so a different texture size breaks exact ties differently).

## Differences, failures and limitations

- Visual: nearest-sampling ties. Where a pixel centre lies on a texel boundary, the atlas offset makes the hardware pick the other texel than the per-image texture did, shifting a sprite edge (or a whole sprite at exact half-texel placement) by one texel. 3 of 8 1080p captures differ by 228-1,311 pixels; at normal size they are indistinguishable. Static atlas sprites already behave this way. The `dynamic_atlas` test classifies every differing pixel as a one-pixel edge shift or as lying within 2e-3 texel of a boundary (about 16× the measured uv float error); 0 unexplained.
- The captures were taken on the fixed 4-page build, before on-demand growth was added. Growth does not change sampling, and the readback test covers resizes, but the 1080p captures were not re-run on the final build (stopped by the user to save time).
- An oversized frame (more than 12 pages of distinct bitmaps visible within two frames) falls back per image; it never shows a blank or wrong texture (readback-verified at 1 page), but those quads cost one draw each again.
- **S3/144 Hz remains unqualified**: S3 mixed-dense p50 13.9 ms, p95 140 ms. The tail is first-seen composition bursts (up to ~3,000 new appearances in one frame); S3 combat cluster is now GPU-bound (8.3 ms with 4 draws).
- variety-512 has 48/600 frames over 33 ms in every configuration including the old path — first-seen composition, unchanged by Q07.
- Pre-existing UBSan report (not Q07): `src/appearance.cpp:23` signed overflow in `world_dyes` when `world_queries` writes non-finite positions; the test passes because UBSan does not halt. Previously unseen because earlier runs did not print passing tests' stderr. Spun off as a separate task.
- `Appearance CPU/GPU` exit line and stress `cache_*` summary fields still describe the per-image caches (now overflow only); dynamic atlas state is in its own exit line and telemetry counters. Mock/offline evidence only.
