## What the profile showed (this changed the plan)

## Implementation

- `include/realm/particles.hpp`, `src/particles.cpp`: `TargetFilter` (4096-bit conservative filters for particle/emitter/flash targets, set at every insertion, rebuilt from live contents once per update); `remove_target`, `attach`, `healing` and the flash replacement skip scans when a filter bit is clear; `Particles::targets(id)` is the exact diagnostic scan. Fixed bounds (8,192/1,024/256) unchanged. Id -1 (untargeted particles) always scans, preserving old behavior exactly.
- `include/realm/entity_index.hpp`, `include/realm/world.hpp`, `src/world.cpp`: `EntityIndex` replaces the id→slot `unordered_map`; `damage_cues_` is a deque and `status_events_` drops its oldest entry in O(1); `World::add` copies decoded default dyes (`ObjectDef::tex1/tex2`, `catalog.hpp/cpp`); `World::remove` searches `interactive_` only for interactive types; `initialize` releases oversized dense-list/table capacity.
- `include/realm/stat_map.hpp`: `StatMap` replaces `Entity::stats` (sorted 8-byte entries, same interface; `World::status` reserves from the first full status). `Entity` 304 → 272 B.
- `include/realm/combat.hpp`, `src/combat.cpp`: `HitSet` (sorted vector, 24 B) replaces the per-projectile `unordered_set` (`FlyingProjectile` 128 → 96 B); `Combat::reset`/`update` release projectile and grid vectors that exceed 8x their size.
- Tests/tools: CTest `world_storage` (`tests/world_storage_tests.cpp`), `tools/quality_pair.py`.
- Not changed: gameplay, protocol, collision, target-grid semantics, `World::update`, `Scene`, particle simulation, appearance/text caches (Q07), `Entity` field layout beyond stats.

## Differences, failures and limitations

- Whole-client S3/144 Hz is still **unqualified**: S3 frames remain 140–800 ms because of name/appearance/text churn (Q07) and the minimap redraw (Q12). The headless gains are real but are collision/hit/removal bookkeeping, not `scene.build`.
- Two >1.05 viewer flags were investigated, not waved off: `S1-players-spread` (1.206, 0.19 -> 0.23 ms absolute) re-ran at 0.953 with 11 repeats; `models-varied-rotating` (1.083, then 1.265 with 11 repeats) is a bimodal p95 over 30 frames in both binaries (ranges 2.8–3.9 ms overlap); a 9-repeat paired trace shows identical zones and frame medians (`scene.build` 0.866 vs 0.870 ms, `frame.cpu` median 2.753 vs 2.732 ms). `nexus-idle` rerun 1.034. No code path those scenarios exercise changed in cost.
- The viewer pair and churn soak ran on the binary built before two small late edits (`EntityIndex::assign` no longer grows the table when re-pointing an existing key; the particle filter skips the untargeted id -1). The full CTest suites, the 505,894-check storage test and the 12-scenario headless pair were re-run after them; the viewer pair was not repeated.
- `TargetFilter` is conservative: with thousands of simultaneously targeted ids the filter saturates and removal falls back to the previous scan cost (never worse than before; the pool bounds are unchanged).
- `StatMap` insertion is O(n) and invalidates iterators/references; no caller kept one across a write (audited all `stats[` writes and `find` uses; compile + tests pass). Stat iteration order is now ascending key (only the stress checksum iterated, and it sorted).
- Per-frame allocations in `scene.build` were measured, not reduced: S2 mixed-spread 26k/frame (10.5k `appearance.lookup`), S2 players-dense 18.8k/frame (2k `text.rasterize`, 1k texture uploads), S2 mixed-dense 52k/frame and 300 MB of image bytes (`appearance.compose`). These are Q06/Q07 (surfaces, appearance/text residency).
- `Entity` was not split hot/cold (not justified by measurement, ~350 call sites); the dense list's power-of-two capacity slack is about half of the per-object bytes in the probe.
- Pre-existing unrelated warnings remain in `tests/dye_session_inputs.cpp`, `tools/skin_inputs.cpp`, `tests/player_menu_tests.cpp`. No required check was disabled or skipped. Mock/offline evidence only; no live-server or new visual captures (painter streams are byte-identical).

## S3 follow-up (same session, user-authorized: "You can finish S3 if you desire")

After Q05 closed, the S3 viewer profile was attacked directly. This goes beyond the Q05 work package into Q07/Q12 territory; it is recorded here, and Q07/Q12 should start from it.

Findings (zone medians, ms, S3 mixed-spread before): `appearance.lookup` 86 (compose 84), `text.rasterize` 16.5, `render.texture_upload` 13, `appearance.gpu_cache` 10, minimap 8.4. Cause: the fixture cycles 512 appearances (x3 sizes) and 556+ visible names through caches of 256 appearances / 160 labels, so cyclic LRU missed on every request; the GPU appearance lookup was a linear scan of a list and the status-surface table cleared itself at 256 entries.

Changes: `Appearances::maximum_entries/bytes` 256/32 MiB -> 4096/64 MiB (GPU copy uses the same bounds); `Scene::surface` and `Scene::status_surface` use identity-indexed LRUs (4096 / 64 MiB for status surfaces); `StatusArt` labels 160/8 MiB -> 4096/64 MiB; appearance cache key is a struct (no string building, no source cropping on hits; textile art cropped once); the processed-texture string key is built only when a processed set exists; `ui_rectangle` shares per-column coverage, skips the blend for fully covered pixels and avoids `lround` (about 3x for 6,000 minimap markers); `Appearances::compose` reuses per-axis spans/buffers and `round_up` (1.8x; `compose_reference` keeps the original as oracle). Texture handles are no longer part of the painter-stream digest (they are renderer names, not content). Budgets stay inside the Q00 limits (about 64 MiB CPU + 64 MiB GPU appearances, 64 + 64 MiB labels, 16 MiB atlas against 256 MiB GPU / 1 GiB RSS).

Results (hidden 1080p viewer, 4 s warmup, 200 measured frames, 3 repeats, vs the pre-Q05 binary; CPU frame ms):

| --- | ---: | ---: |
| S3-mixed-spread | 168.8 / 181.5 / 198.8 | **19.5** / 103.2 / 112.1 |
| S3-mixed-dense | 792.1 / 818.4 / 826.7 | **29.8** / 363.6 / 534.3 |
| S3-combat-cluster | 224.7 / 257.7 / 287.7 | **23.6** / 43.1 / 53.9 |

Equivalence: against a binary built with the pre-follow-up cache/key/`ui_rectangle` sources (same digest), state, packet, hit and painter-stream digests are identical in 15/15 scenarios (`build/quality-Q05/final/pair-s3b`). New differentials: `ui_rectangle` (80,000 random rectangles, byte-identical) and `appearance_compose` (compose vs `compose_reference`, 1,365 real/synthetic cases, byte-identical); `dye_tests`, `status_rules_tests` adjusted to the new bounds. Release **56/56**, ASan/UBSan **49/49**, graphics sanitizer subset **24/24** (the compose test was trimmed afterwards to keep sanitizer time reasonable; it was re-run alone).

Limits, stated plainly: **S3/144 Hz (6.94 ms) is still unqualified.** Steady spread frames are ~19 ms: `scene.build` ~8 ms (about 18,000 projectiles at ~0.3 us each plus ~900 actors), simulation 5 ms (combat 3.6), `render.submit` 2.8, HUD/minimap 3.5, sorting 1. p95/p99 are first-appearance composition hitches (up to ~500 new composes in one frame, ~100 ms) that only prewarming, a per-frame budget or worker threads (Q07/Q18) can remove. Dense frames also pay ~18,600 draw calls (one GL texture per composed appearance): atlas/array batching is Q07. Closing the remaining 3x needs a batched/instanced projectile path (Q06/Q07), not more per-entity trimming.
